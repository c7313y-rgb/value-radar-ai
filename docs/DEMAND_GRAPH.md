# 需要連鎖グラフ（Demand Graph）

`engine/demand/graph.py` に 45ノード・44エッジの有向非巡回グラフとして定義されています。

## 1. なぜグラフなのか

「AI関連銘柄」というタグ付けでは、**NVIDIA が上がりきった後にどこへ行くべきか**が分かりません。
必要なのは分類ではなく因果です。

```
生成AI設備投資 ──(3ヶ月, 0.90)──▶ GPU・AIアクセラレータ
              ──(6ヶ月, 0.85)──▶ データセンター建設
                                   ──(4ヶ月, 0.90)──▶ DC電力設備
                                        ──(5ヶ月, 0.85)──▶ UPS・配電盤
                                             ──(6ヶ月, 0.80)──▶ 変圧器
                                                  ──(7ヶ月, 0.85)──▶ 送配電網
                                                       ──(10ヶ月, 0.70)──▶ 発電設備
```

各エッジの `(lag_months, elasticity)` が「いつ・どれだけ」需要が届くかを表します。
生成AI設備投資から変圧器までは累積で**約21ヶ月**。この時間差こそが先回りの余地です。

## 2. ドライバー（一次需要の源泉）

| ノード | 内容 |
|---|---|
| `genai_capex` | 生成AI設備投資 |
| `electrification` | 電化・EV転換 |
| `labor_shortage` | 労働力不足・省人化 |
| `geopolitics` | 地政学・防衛費 |
| `demographics` | 高齢化・人口動態 |
| `macro_cycle` | 景気・金利サイクル（構造要因ではなく循環要因） |

ドライバーには上流がありません（テストで固定）。

## 3. 需要圧力の計算

```python
inflow   = Σ_parents [ (親の変化×0.75 + (親の水準−50)×0.25) × elasticity × lag_weight ]
lag_weight(m) = 0.35 + 0.65 × exp(−m / 18)      # 遅いほど割り引くが、ゼロにはしない
pressure = 50 + 0.45×(自ノードの実需水準−50) + 0.35×自ノードの変化 + 0.45×inflow
```

トポロジカル順に上流から流すので、三次・四次ノードには上流全体の勢いが累積します。
**水準ではなく変化を主に流している**のがポイントです。水準だけを流すと、
「もともと大きい産業」が常に上位に来てしまいます。

## 4. 織り込み度と未織り込みギャップ

```python
priced_in = Σ_companies 露出度 × (0.60×割高パーセンタイル + 0.40×モメンタムパーセンタイル) / Σ露出度
unpriced_gap = (pressure − priced_in) × (1 + 0.06 × max(0, depth−1))
```

`depth` が深いほど「誰も見ていない場所」なので発見価値を微加点します。
需要圧力が 55 未満のノードは候補から除外します（「安いだけ」は機会ではない）。

## 5. 企業の Trend レイヤー得点

```python
score = Σ_nodes 露出度 × (pressure + max(0, unpriced_gap) × 0.30) / Σ露出度
# テーマとの接点が薄い企業（露出合計が小さい）は中庸に寄せる
```

## 6. ノードを追加する

1. `NODES` に `Node(id, label, desc, signals, is_driver=False)` を足す
2. `EDGES` に上流からのエッジを足す（**必ず非巡回に保つ**。`validate()` が検査）
3. `engine/universe.py` の企業に露出度を設定する（`nodes={"新ノード": 0.3}`）
4. `DemoEvidenceProvider.BASE` に基調値を足す（デモ用）
5. テストを走らせる（露出キーがグラフに無いと落ちます）

```bash
python3 -m engine.demand.graph      # 全ノードの段数と因果経路を表示
python3 -m unittest tests.test_graph
```

## 7. 実データのエビデンスに差し替える

`EvidenceProvider` プロトコル（`providers/base.py`）を実装し、
`registry.get_evidence_provider()` に登録します。返すのは `EvidenceItem` のリストだけです。

実装候補となる一次情報源：

| シグナル | 情報源の例 |
|---|---|
| 受注残・受注高 | 各社決算短信・10-Q、日本工作機械工業会の受注統計 |
| 設備投資計画 | 決算説明資料、日銀短観、SEMI の装置投資予測 |
| 政府予算・補助金 | 各省庁の予算書、経産省の補助金公募、米 DOE/CHIPS 法 |
| 求人数 | 各社採用ページ、求人統計 |
| 工場・DC着工 | 建築着工統計、各社プレスリリース、自治体の開発許可 |
| 電力需要 | 電力広域的運営推進機関、EIA、系統接続申請キュー |
| 出荷統計 | SIA/WSTS、経産省 生産動態統計 |
| リードタイム | 業界誌、決算説明での言及 |
| 特許出願 | 特許庁、USPTO、Google Patents |
| 経営者発言 | 決算説明会の書き起こし |

**注意：** ニュースのスクレイピングは各サイトの利用規約に従ってください。
本リポジトリはスクレイパを同梱していません。
